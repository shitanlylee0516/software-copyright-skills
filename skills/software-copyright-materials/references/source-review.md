# 源代码鉴存前审查与源程序 Word 规范排版指引

本指引规范在提交中国计算机软件著作权登记材料时，源代码的初审、清洗、物理行数统计，以及最终法定鉴存 Word (`.docx`) 文档的标准化排版工作流。

## 一、审查与审计定位

- **自审工具定位**：`collect_source.py` 脚本定位为**内部代码初审、清单清点、物理行数统计与格式合规性检查工具**。
- **文件排除初选 vs 法定连续鉴存**：必须严格区分“工程级敏感文件/依赖排除初选”与“法定连续源程序鉴存”。《计算机软件著作权登记办法》要求提交源程序前、后各连续 30 页（或全部代码）。本工具仅帮助开发者从工程中预先挑选并核实合法代码清单，生成内部审查合规包；严禁将非连续的零碎代码随意组合当做法定提交件。
- **关于行数与页数**：不得武断将“3000 行代码”等同于“60 页鉴存文档”。实际排版页数取决于每页物理行数、排版字体、行距与折行情况（法定要求通常每页不少于 50 行）。

## 二、代码筛选与清洗准则

在确定清单（Manifest）中的源程序文件时，应遵循以下准则：

1. **排除敏感文件名（本工具检测边界）**：
   - 工具内置了对敏感路径组件的拦截：如 `.env` 开头文件/目录、`credentials.json`、`secrets.json`、`id_rsa`、私钥/证书扩展名（`.key`, `.pem`, `.p12`, `.pfx` 等）。
   - **注意**：本工具仅检查高风险的文件名与路径组件，**无法自动检测代码文本内部硬编码的机密凭据或商业机密**。申报人员在提交前必须进行全面的人工敏感信息排查。

2. **保留业务与自研核心**：
   - 优先选择具有原创性、承载核心算法、数据模型、业务流程的源码文件。
   - 排除外部第三方未经二次开发的开源库、Vendor 依赖包（如 `node_modules/`、`vendor/`、`dist/` 编译产物）。
   - 排除不可作为人类可读源程序的二进制文件（如 `.exe`、`.dll`、`.so`、`.class`、`.pyc` 等）。

3. **编码规范与文本完整性**：
   - 必须全部采用 UTF-8 编码且无二进制空字符（NUL byte `\x00`）。保持原始代码格式与换行符不变（缩进与代码逻辑），避免自动格式化工具破坏代码语法。

4. **入口权重优先排序**：
   - 源代码合并顺序应遵循逻辑主线，建议权重：
     - 第一顺位：前端/系统主入口（如 `index.html`，带有 `<!DOCTYPE html>` 首行）
     - 第二顺位：主执行脚本或启动文件（如 `src/main.tsx` 或 `src/index.js`）
     - 第三顺位：应用根组件或服务总线（如 `src/App.tsx`）
     - 后续顺位：核心业务领域算法、路由驱动与专属交互组件。

## 三、行数统计原则

- **物理行（Physical Lines）计算**：通过对文件原始二进制内容按换行符（`splitlines()`）进行统计，确保物理行真实反映文件结构（空文件计为 0 行）。
- **非软件总行数声明**：该统计值仅代表**清单中所选定审查文件的物理行合计**，并不等同于整个软件系统的全部工程代码量。

## 四、法定源程序鉴存 Word 规范生成（`build_source_docx.py`）

依据国家版权局《计算机软件著作权登记办法》第十条及行业通行规范，最终交存的源程序必须为规范排版的 Word (`.docx`) 或 PDF 文档。Skill 内置的 `build_source_docx.py` 严格实现以下标准：

1. **纸张与页边距**：
   - 纸张规格：标准 A4（21.0 cm × 29.7 cm）；
   - 页边距：上 2.50 cm、下 2.50 cm、左 2.00 cm、右 2.00 cm；
   - 装订线：0 cm，页眉距顶端 1.50 cm，页脚距底端 1.50 cm。

2. **字体与字号**：
   - 全文代码、英文、中文注释及特殊符号统一固定为 **`宋体`（SimSun）**；
   - 字号严格锁定为 **`8.5 pt`（小五号）**；
   - 段落缩进：首行缩进 0 字符，左/右缩进 0 字符；
   - 段落间距：段前 0 pt，段后 0 pt；
   - 行距设置：**固定值 12.0 pt**（`WD_LINE_SPACING.EXACTLY, Pt(12)`）。

3. **连续流淌分页机制**：
   - **严禁在代码正文中插入任何物理分页符**（PageBreak），让单行代码依靠固定行距与版心边界自然折行、流淌分页；
   - 确保每页平均容纳 55~58 行代码（完全满足法定每页不少于 50 行的审查红线）。

4. **页眉版式与动态页码绝对右对齐**：
   - 采用 1 行 2 列无框表格布局（版心净宽 17.0 cm / 9638 dxa）：
     - **左单元格**（宽度 6236 dxa）：左对齐，格式为 `{软件全称} {版本号} 源代码`，宋体 9 pt 黑色；
     - **右单元格**（宽度 3402 dxa）：强制绝对右对齐（`w:jc w:val="right"`），嵌入原生 OpenXML 动态域代码 `第 PAGE 页 共 NUMPAGES 页`，宋体 9 pt 黑色；
     - **底部分割线**：单元格下方添加 0.75 pt 单细实线（色值 `#999999`）；
   - **首页连续编号**：取消首页不同（`different_first_page_header_footer = False`），从第 1 页即开始显示页眉与页码。

5. **法定节选与 60 页控制算法**：
   - **总行数 ≤ 3,500 行**：全量连续输出排版（实际页数约 25~58 页），符合版权局“源程序不足 60 页应当全量提交”的法定准则；
   - **总行数 > 3,500 行**：自动执行法定截选，取**前 1,700 行** + 连续过渡注释行 `// [... 中间部分已省略 ...]` + **后 1,700 行**，渲染后**精准稳定为 60 页**（前 30 页 + 后 30 页）。

使用示例：
```bash
python skills/software-copyright-materials/scripts/build_source_docx.py \
  --input /path/to/cleaned_source.txt \
  --output /path/to/source_code.docx \
  --name "软件全称" \
  --version "V1.0"
```
